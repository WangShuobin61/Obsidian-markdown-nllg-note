# 十一、面试前AI简历分析

这份简历整体风格属于“培训/包装痕迹较重 + 项目堆砌型”，但并不一定完全造假，更像是“学校/培训项目 + 少量实际工作”的组合。  
如果你司岗位是偏：

- Linux嵌入式
- Qt上位机
- 设备通信
- 网络通信
- 工控/物联网

那他“可能能干活”，但需要重点验证：

1. 是否真正写过代码
2. 是否理解底层原理
3. 是否只是“跟着教程做项目”
4. Qt/网络/驱动到底深到什么程度
5. 是否具备工程化能力

---

# 2. “大型软件开发经验”明显夸张

他只有1年经验。

但写：

- 大型软件开发经验
- 高并发高可用
- 服务注册发现
- 分布式云存储
- 对象池化
- 反向代理

这非常像培训班项目包装。

尤其：

> “基于高并发、高可用、适度冗余和均衡负载的分布式云存储技术”

这种话像课程介绍，不像个人项目描述。

---

# 3. 分布式流媒体项目疑似培训班项目

高度像经典 Linux/C++ 培训项目。

特征：

- ACL
- VLC
- Redis
- GlusterFS
- Tracker/Storage Server
- WebServer
- Qt播放器

这一套很像某些培训机构“大作业”。

重点要问：

- 你到底负责了什么
- 为什么这样设计
- 网络协议细节
- 数据流转过程
- 是否真正调试过

因为很多人只是：

- 改配置
- 跑demo
- 抄代码

---

# 4. Linux驱动部分可信度要重点验证

他写了：

- input子系统
- platform总线
- 中断
- i2c
- ioctl
- UVC
- 内核定时器
- 字符设备驱动

如果这些都真做过：

那已经不止8-10k。

所以这里很可能：

- 做过实验
- 看过教程
- 改过demo

但未必真理解。

---

# 5. “精通MQTT协议”大概率夸张

很多人：

- 会调库
- 会连阿里云
- 会pub/sub

就写“精通”。

真正问：

- QoS机制
- retain
- keepalive
- clean session
- reconnect
- 遗嘱消息
- MQTT报文结构

马上露馅。

---

# 6. Qt经验需要重点验证

简历里Qt写得很大：

- 多主题
- 跨平台
- 全流程
- 核心模块

但没有：

- Model/View
- QThread
- QObject线程归属
- 信号槽跨线程
- QML
- 事件机制

说明Qt深度可能一般。

# 二、总体判断

我会倾向判断：

|项目|评价|
|---|---|
|C语言基础|可能还可以|
|Linux基础|中等偏初级|
|Qt|有实际使用|
|驱动|大概率偏实验性质|
|网络编程|有一定实践|
|工程能力|存疑|
|架构能力|明显包装|
|真正独立开发能力|需要验证|

如果你司：

- 需要能快速培养的人 → 可以考虑
- 需要成熟独立开发 → 风险较大
