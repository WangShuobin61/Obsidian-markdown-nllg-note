# 站群源码分布与云端发布工作流

> 核对日期：2026-11-19 · 适用范围：个人官网、个人履历、RowSeat 产品官网与 Web App。Minecraft 用于说明独立服务的交付形态。

## 1. 服务端实际保存什么

服务器同时存有**静态网站产物、可直接运行的后端源码、编译生成的模块以及可执行程序**。完整开发工程和 Git 历史由开发机及代码托管仓库管理。线上运行目录按各服务的执行需求放置文件。

| 服务 | 线上目录或入口 | 实际交付形态 |
| --- | --- | --- |
| 个人官网、个人履历、RowSeat 产品官网、RowSeat Web 前端 | `/srv/nllg-sites/<对应域名>/` | Nginx 直接提供 HTML、CSS、浏览器 JavaScript 和图片等资源。官网目录里即使有名为 `src` 的目录，也应按实际发布文件理解；开发工程中的 TSX、构建配置和 Git 历史另行管理。 |
| RowSeat 账号与站群 API | `/opt/rowseat/identity/server/index.mjs` | systemd 启动 Node.js 24 执行 `index.mjs`，再加载 `app.mjs`、认证、邮件、存储等可读的 JavaScript 模块。工作区数据校验使用从 TypeScript 构建出的 `server/generated/workspace-schema.mjs`。服务器有运行所需的业务代码和依赖。 |
| 个人官网博文接口 | `/opt/nllg/gitee-reader/index.mjs` | Node.js 执行 `index.mjs` 和 `notes.mjs`。打开文章时按需读取 Gitee；网站发布包只包含前端页面和资源。 |
| 贡献与 Token 热力图 | `/opt/nllg/public-activity/scripts/` | 定时器调用 Node.js 脚本生成公开 JSON，两站在运行时读取各自域名下的 `/activity/latest.json`。图表布局、标签和样式属于另外一条前端发布链路。 |
| Minecraft 基岩版与 QQ 机器人 | `/srv/minecraft-bedrock/current/`、`/opt/minecraft-qqbot/` | 游戏本体 `bedrock_server` 是 Linux x86-64 ELF 可执行文件。控制台监督器 `console-supervisor.py` 和 QQ 机器人 `bot.py`、`monitor.py` 是在服务器上运行的 Python 脚本。 |

RowSeat 的生产配置和 SQLite 数据位于运行目录之外。数据库包含账号与已同步的业务数据，应该独立备份。提交 Git、重新打包前端或安装静态网站均无需复制生产数据库，也无需带上生产环境变量、私钥或证书。

## 2. 本机修改、验证与推送

完整流程是 **本地改源码 → 测试与构建 → Git 提交 → 推送对应云端仓库 → SSH 发布 → 线上验收**。目前 Gitee 保存代码和提交历史，生产站点由部署步骤更新。单独执行 `git push` 不会把文件安装到线上。

开发工作区下，这几个目录各有用途：

| 本机目录 | 验证与构建 | 作用 |
| --- | --- | --- |
| `逆旅流光-个人官网/nllg-home` | `npm.cmd run build` | 运行静态站构建脚本，生成 `dist/`。首页热力图从同级履历项目构建共用组件。 |
| `逆旅流光-个人官网/nllg-portfolio` | `npm.cmd test`、`npm.cmd run build` | 执行回归测试，做 TypeScript 检查和 Vite 构建。发布时使用带内容指纹的资源文件。 |
| `智慧教室-智能排座/website` | `npm.cmd test`、`npm.cmd run build` | 验证并打包 RowSeat 产品官网。 |
| `智慧教室-智能排座/RowSeat` | `npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run build` | 检查类型、运行测试、生成 Web 前端和服务端校验模块。修改账号等服务端逻辑时，再跑 `npm.cmd run test:server`；该命令会重建校验模块并运行服务端测试。 |

新检出仓库或锁文件变化后，先在对应项目目录运行 `npm.cmd ci`，按锁文件安装依赖。针对两个站点共用的热力图，修改在履历仓库提交，个人官网和履历分别构建、分别部署。

在对应 Git 仓库根目录运行以下命令。示例中的源码和测试文件路径应替换为本次实际修改的路径。

```powershell
git status --short --branch
git diff
git add -- <源码文件> <测试文件>
git diff --cached --check
git diff --cached --stat
git commit -m "说明本次改动"
git push
```

| 命令 | 作用 |
| --- | --- |
| `git status --short --branch` | 查看当前分支、上游关系、暂存和未提交文件。 |
| `git diff` | 检查工作树改动，确认同一文件里是否还有其他任务的未提交内容。 |
| `git add -- <文件>` | 暂存本次文件。文件内混有其他任务时，可用 `git add -p -- <文件>` 按块暂存。 |
| `git diff --cached --check`、`--stat` | 检查暂存区的空白错误和改动范围。 |
| `git commit -m`、`git push` | 创建本地提交，随即推送到当前分支的云端上游。 |
| `git rev-parse HEAD`、`git ls-remote origin refs/heads/main` | 分别查看本地提交和 Git 远端分支指向。使用 `master` 或其他分支时替换引用。 |

## 3. 静态站日常增量发布

近期履历和热力图更新走的是增量发布。先核对线上入口所引用的 JS、CSS 及关联动态加载的资源，再选择干净的发布输入。如果本机工作树还包含其他修改，就用与线上资源校验值一致的构建底稿，只应用本次已验证的改动。这样可以避免把其他工作内容一并发布。

发布包只放本次入口页、变更后的指纹资源和它们需要的新分块。将这些文件按站点目录结构放进暂存目录，再在 Windows 打包并上传。以下示例以履历为目标。先将 `$stage` 设为本机暂存目录、`$deployHost` 设为已经核对的 SSH 目标或别名、`$sshOptions` 设为已有连接参数数组。连接沿用已核验的主机记录并启用严格主机检查。

```powershell
$archive = Join-Path $PWD 'resume-release.tar.gz'
tar.exe -czf $archive -C $stage index.html assets sha256.txt
Get-FileHash -Algorithm SHA256 $archive
scp @sshOptions $archive "${deployHost}:~/resume-release.tar.gz"
ssh @sshOptions $deployHost
```

`tar.exe` 把暂存文件归档，`Get-FileHash` 计算本地归档哈希，`scp` 上传归档，`ssh` 进入服务器。暂存目录中的 `sha256.txt` 记录每个公开文件的哈希；可在生成发布包时用 `Get-FileHash` 或脚本计算，格式为 `<SHA-256>  <包内相对路径>`。

服务器侧按以下顺序执行：

1. `sha256sum ~/resume-release.tar.gz` 与本地结果比较；用 `tar -xzf` 解包到 `mktemp -d` 创建的临时目录，在该目录运行 `sha256sum -c sha256.txt` 验证每个文件。
2. 用 `sha256sum` 再确认服务器正在提供的旧入口仍是打包时核对的版本，并用 `sudo cp -p` 备份入口到独立备份目录。
3. 用 `sudo install -m 0644` 先安装新 JS、CSS 和动态分块。通过 HTTPS 请求资源，核对状态和哈希。
4. 将新 `index.html` 复制到网站目录内的临时文件，再用 `sudo mv -f` 原子替换正式入口。旧指纹资源可继续服务已经打开的页面。
5. 用 `curl -fsS` 检查公开首页，再用浏览器检查受影响页面和交互。若发布后校验失败，用备份入口恢复并重新验证。静态页面更新无需重启 Node.js 或 Nginx。

例如，核查线上入口和公开接口可使用：

```bash
curl -fsS https://resume.nllg2026.xyz/ | sha256sum
curl -fsS https://resume.nllg2026.xyz/activity/latest.json -o /dev/null
curl -fsS https://app.rowseat.nllg2026.xyz/api/public/version
```

## 4. 四站整包安装

首次安装或确有整站替换需要时，可以使用仓库内的打包与安装脚本。先完成四站构建，再在智慧教室仓库根目录执行：

```powershell
node scripts/deploy/package-sites.mjs --portfolio-root '../逆旅流光-个人官网/nllg-portfolio' --home-root '../逆旅流光-个人官网/nllg-home' --enable-identity
$release = Get-Content 'output/server-deploy/latest-fixed.json' -Raw | ConvertFrom-Json
$archive = Join-Path $PWD 'sites-release.tar.gz'
tar.exe -czf $archive -C $release.directory manifest.json sites
Get-FileHash -Algorithm SHA256 $archive
```

`package-sites.mjs` 从各项目的 `dist` 读取公开资源，补齐引用的履历素材，写入文件路径、大小和哈希清单。`--enable-identity` 让正式 Web App 使用已部署的账号 API；参数本身不会安装后端。通过 `scp` 上传归档以及已核对版本的 `scripts/deploy/install-fixed.py`。在服务器上核对归档哈希后执行 `sudo python3 ~/install-fixed.py ~/sites-release.tar.gz`。

安装器校验清单与文件后替换站点目录，安装过程异常时可恢复原目录。成功后如需人工回退，应使用发布前单独保留的备份。四站完整归档配合默认安装模式；`--site` 需要为目标单站专门生成的清单和归档。少量前端修改优先走增量发布。

## 5. 后端服务发布与验收

修改 API、邮件、认证或博文按需读取逻辑时，分别构建和验证对应模块。RowSeat 的 `npm.cmd run build:server` 生成 Node 可执行的 JavaScript 校验模块，其他手写 `.mjs` 由 Node 直接加载。将变更模块及变更所需依赖单独部署到服务的运行目录；依赖锁有变化时，在对应 Linux 运行环境按锁文件安装生产依赖。

先备份将替换的服务文件。安装后语法检查通过，再重启对应 systemd 单元并做功能验收。以下是用于确认和验证的命令，其中 `<Node路径>` 从服务的 `ExecStart` 取得：

```bash
systemctl show rowseat-identity.service -p WorkingDirectory -p ExecStart
<Node路径> --check /opt/rowseat/identity/server/app.mjs
sudo systemctl restart rowseat-identity.service
systemctl is-active rowseat-identity.service
sudo journalctl -u rowseat-identity.service -n 50 --no-pager
curl -fsS https://app.rowseat.nllg2026.xyz/api/public/version
```

| 命令 | 作用 |
| --- | --- |
| `systemctl show` | 确认服务的工作目录、运行时和入口。 |
| `node --check` | 检查 JavaScript 语法，实际依赖与 API 行为由测试和上线探测验证。 |
| `systemctl restart` | 让 Node 进程重新加载已部署的代码。只重启本次修改对应的服务。 |
| `systemctl is-active`、`journalctl -u` | 查看进程状态和指定服务的近期日志。 |
| `curl -fsS` | 通过公开 HTTPS 域名核查路由、反代和响应，HTTP 错误时返回非零状态。 |
| `sudo nginx -t`、`sudo systemctl reload nginx` | 修改反向代理或 Nginx 配置时使用，先测试配置，再平滑重载。 |

博文服务使用 `nllg-gitee-reader.service`，上线后从个人官网打开文章验证。定时任务用 `systemctl list-timers nllg-public-activity.timer` 看下次触发时间，用 `journalctl -u nllg-public-activity.service` 看生成结果。若后端健康检查失败，恢复已备份的模块并重启对应服务，复查接口和日志。

可在开发工作区继续查阅 `docs/四站固定目录与上线进度.md`、`docs/统一身份认证接入.md` 以及 RowSeat 仓库的 `doc/远程连接服务器工作流.md`。
