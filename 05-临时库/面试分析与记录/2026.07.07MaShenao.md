# 八、面试前AI简历分析

## 简历明显“硬风险点 / 水分信号”

这份简历整体属于“**技术栈堆得很满，但工程可信度需要验证**”类型，重点风险如下：

## 1. 技术覆盖面异常“过宽且跨领域”

同时出现：

- ROS2 / Nav2 / SLAM Toolbox / Cartographer
- FFmpeg + RTMP协议栈级实现
- MFC游戏客户端 + MMORPG服务器
- IOCP + epoll + DDS + FastDDS
- Gazebo + URDF + 机械臂控制 + Web HTTP + 大模型接口

👉 典型问题：

> 一个 0-2 年经验开发者同时“深度参与协议栈 + 游戏服务器 + 机器人 + 流媒体底层实现”，**明显偏宽泛全栈化包装**

---

## 2. “协议栈/底层实现”描述偏夸张

例如：

- “实现RTMP握手、AMF0解析”
- “FFmpeg H264解码YUV420P可视化”
- “IOCP完成端口并发接入”
- “DDS QoS设计”

👉 风险点：  
这些通常是：

- 要么只是**调用库**
- 要么是**参与调试/封装接口**  
    而非“实现协议/核心逻辑”

---

## 3. ROS2部分描述“偏配置工程化而非算法/系统深度”

大量出现：

- Nav2参数调优
- QoS配置
- topic/service调试
- launch文件
- rviz验证

👉 说明可能：

- 偏“ROS集成工程师”
- 而非“ROS系统开发 / 算法工程师”

---

## 4. 游戏服务器 + ROS机器人“双主线”

- MMORPG服务器（任务系统/A*/数据库/协议）
- 四足机器人（ROS2+SLAM+Nav2）
- 仿真机器人（Gazebo+机械臂）

👉 常见问题：

> 真实工作中很难在1年内同时深度参与这三类完全不同体系

---

## 5. 关键缺失信息

- 没有量化指标（性能、延迟、帧率、机器人成功率）
- 没有明确“独立负责 vs 参与模块”
- 没有代码规模 / 架构图 / 设计边界
