“编译时（Compile Time）” 和 “运行时（Run Time）” 是程序开发里两个非常核心的概念，本质上可以理解为：

- **编译时**：代码“变成可执行程序”的阶段
- **运行时**：程序“真正开始执行”的阶段

你可以把它理解成：

| 阶段   | 类比                         |
| ------ | ---------------------------- |
| 编译时 | 厨师备菜、检查菜单、做预处理 |
| 运行时 | 顾客真正点菜、开始炒菜上桌   |

* * *

# 一、什么是编译时

编译时指：

>
> 代码还没运行，只是在“编译器检查和转换代码”的阶段。

比如 C/C++：

    int a = "hello";

编译器一看：

- `a` 是 int
- `"hello"` 是字符串

类型不匹配。

于是：

- 程序还没运行
- 编译器就直接报错

这就叫：

>
> 编译时错误（Compile-time Error）

* * *

## 编译时主要干什么

编译器会做很多事情：

### 1. 语法检查

比如：

    if (a > 0

少了个 `)`。

编译器直接报错。

* * *

### 2. 类型检查

    int a = "abc";

类型不对。

* * *

### 3. 模板展开（C++）

    template<typename T>

会在编译时生成代码。

* * *

### 4. 宏展开

    #define PI 3.14

编译前替换。

* * *

### 5. 优化

比如：

    int a = 1 + 2;

编译器可能直接算成：

    int a = 3;

这叫：

>
> 编译时计算

* * *

# 二、什么是运行时

运行时指：

>
> 程序已经启动，CPU 真正在执行代码。

例如：

    int a = 10;int b = 0;int c = a / b;

编译能通过。

因为：

- 语法没错
- 类型也没错

但程序运行到：

    a / b

时：

除数是 0。

于是：

程序崩了。

这就是：

>
> 运行时错误（Runtime Error）

* * *

# 三、最经典区别

## 编译时能确定

    const int a = 3;int arr[a];

数组大小在编译时已知。

* * *

## 运行时才知道

    int a;scanf("%d", &a);int arr[a];

用户输入后才知道数组多大。

这是运行时数据。

* * *

# 四、Qt / 嵌入式里的理解

你是做 Qt / 嵌入式方向，这个概念会经常遇到。

* * *

## Qt里的例子

### 编译时

    connect(btn, &QPushButton::clicked, this, &MainWindow::onClicked);

新语法：

- 信号槽参数类型
- 函数是否存在

很多问题编译时就能检查。

* * *

### 运行时

QML：

    text: backend.someValue

如果：

- backend没注册
- 属性不存在

通常是程序运行后才报错。

* * *

# 五、嵌入式里的例子

## 编译时确定

    #define UART_BAUDRATE 115200

固件编译时已经写死。

* * *

## 运行时决定

    if(receive_cmd() == START)

是否收到指令：

只有程序跑起来后才知道。

* * *

# 六、为什么这个概念重要

因为很多技术都会强调：

* * *

## “编译时安全”

比如：

- Rust
- C++模板
- Qt新信号槽
- 静态类型语言

意思是：

>
> 尽量在程序运行前发现问题。

因为：

运行时出错代价很高。

尤其：

- 工业控制
- 自动驾驶
- 机器人
- 医疗设备

* * *

## “运行时灵活”

比如：

- Python
- JavaScript
- QML
- Lua

优点：

- 动态
- 灵活
- 开发快

缺点：

- 很多问题只能运行后发现

* * *

# 七、一句话总结

可以简单记：

| 名词   | 本质                         |
| ------ | ---------------------------- |
| 编译时 | 程序还没跑，编译器在检查代码 |
| 运行时 | 程序已经启动，CPU 真正在执行 |

或者：

>
> 编译时是“准备阶段”，运行时是“实战阶段”。
