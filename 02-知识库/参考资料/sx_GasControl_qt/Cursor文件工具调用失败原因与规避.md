# Cursor 文件工具调用失败原因与规避

## 1. 已出现的问题

### 1.1 读取提示 `Read path is required`

原因是调用读取接口时传入了错误的参数名：使用了 `file_path`，接口实际要求 `path`。

使用正确的 `path` 参数，文件可以正常读取。

### 1.2 写入提示 `decode write args failed: unexpected end of JSON input`

这是工具请求参数的 JSON 在解析前不完整，属于一次调用层的序列化或传输失败，不代表目标文件内容本身有问题。

## 2. 后续降低失败概率的方式

1. **严格使用接口要求的参数名**：读取和写入路径统一使用 `path`，并优先传绝对路径。
2. **编辑前先读取文件**：确认目标文件存在并取得最新内容，避免覆盖用户或其他修改。
3. **已有文件优先局部替换**：只修改需要变化的片段，尽量避免把整个大文件重新写入。
4. **新建或必须整体写入时控制单次内容规模**：避免在一次请求中混入无关的大段文本、复杂转义内容或超长字符串。
5. **写入后立即回读验证**：至少检查文件开头、结尾和关键段落；重要文件同时确认行数、文件大小及 UTF-8 编码。
6. **调用报错后先回读，不直接判断文件状态**：确认文件是否未改、写入完整、被截断或变为空文件，再决定是否重试。
7. **重试时保持内容不变**：首次发生 JSON 解码错误时可直接重试一次，避免同时修改内容而无法判断问题来源。
8. **连续失败时停止重复写入**：记录 Cursor 版本、工具名称、完整错误、目标路径、文件大小和重试结果，再进行问题排查或提交 Cursor issue。



## 3. 推荐操作顺序

```text
读取目标文件
    ↓
确认最新内容与目标路径
    ↓
优先执行小范围修改
    ↓
写入后回读关键内容
    ↓
验证失败时保留现场并记录错误
```



## 4. 当前结论

此前“读取必然失败”和“较大文件经常被写成空文件”的现象，在更新 Cursor 并使用正确参数后没有稳定复现。目前能够确认的问题是：一次读取参数名使用错误，以及一次可通过重试恢复的请求 JSON 解码失败。
