# 工业摄像头低延迟方案

> 问题：ROS2 RTSP 拉流节点存在约 1-3 秒延迟，影响遥控操作体验
> 目标：将延迟降至 ms级 可接受范围

---

## 一、延迟根因定位

### 1.1 ffplay 对比测试结论

ffplay 使用 OpenCV 默认拉流时延迟大（~1s），但加上低延迟参数后延迟明显改善：

```bash
# ❌ 延迟高（约 1-3s）
ffplay -rtsp_transport tcp rtsp://admin:123456@192.168.1.123:554/stream1

# ✅ 延迟低
ffplay -rtsp_transport tcp -max_delay 100 -fflags nobuffer -flags low_delay -framedrop rtsp://admin:123456@192.168.1.123:554/stream1
```

**结论：可以修改客户端侧（FFmpeg 解码缓冲区）来降低延迟。**

### 1.2 各参数作用

| `-fflags nobuffer` | 禁止输入缓冲区，帧到即处理 |
| `-flags low_delay` | 编解码器低延迟模式 |
| `-framedrop` | 解码跟不上时自动丢帧 |
| `-max_delay 100`  | 最大延迟 100ms，超时丢弃 |
| `-rtsp_transport tcp`  | 强制 TCP 传输 |

## 二、方案

### 改用 GStreamer 后端

#### 原理

OpenCV 的 `cv::VideoCapture` 支持多个后端，默认用 FFmpeg，可以换成 **GStreamer**。GStreamer 允许传入完整的 Pipeline 字符串，所有低延迟参数都能精确控制。

#### 效果预期

```bash
# GStreamer Pipeline 实现的等效 ffplay 低延迟配置
rtspsrc location=rtsp://... latency=0 ! rtph264depay ! h264parse ! ...
```
- **延迟：ms级**（与 ffplay 低延迟模式相当）
#### 前置依赖

```bash
sudo apt install \
  libgstreamer1.0-dev \
  libgstreamer-plugins-base1.0-dev \
  gstreamer1.0-plugins-bad \
  gstreamer1.0-plugins-ugly
```

```cpp
// 用 FFmpeg 后端
cap_.open(rtsp_url_, cv::CAP_FFMPEG);

// 用 GStreamer 后端，传入低延迟 pipeline
std::string pipeline = 
    "rtspsrc location=" + rtsp_url_ + " latency=0 ! "
    "rtph264depay ! h264parse ! "
    "avdec_h264 ! videoconvert ! "
    "video/x-raw,format=BGR ! appsink";
cap_.open(pipeline, cv::CAP_GSTREAMER);
```

## 三、实施

### Step 1：确认 GStreamer 可用性

```bash
# 安装依赖
sudo apt install libgstreamer1.0-dev libgstreamer-plugins-base1.0-dev \
                 gstreamer1.0-plugins-bad gstreamer1.0-plugins-ugly

# 验 OpenCV 是否已编译 GStreamer 支持
python3 -c "import cv2; print(cv2.getBuildInformation())" | grep GStreamer
```

### Step 2：用 GStreamer 命令测试低延迟

```bash
# 用 gst-launch 验证低延迟效果（相当于 ffplay 低延迟模式）
gst-launch-1.0 rtspsrc location=rtsp://admin:123456@192.168.1.123:554/stream1 \
  latency=0 ! rtph264depay ! h264parse ! avdec_h264 ! autovideosink
```
